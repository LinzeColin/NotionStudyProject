# 学习项目编排器

本文件是**薄入口**，不是规则本体。规则活在仓库里并跟着 GitHub 迭代 —— 这样换机器、换 Agent 都不会退回旧版本。

## 先读这些（顺序固定）

1. `AGENTS.md` —— 根合同：角色、四道门、项目登记、教学硬规则、何时写入
2. `SKILL_RULES_CHECKLIST.md` —— 本 Skill 的完整规则清单 `S01`–`S43` 与冲突裁决
3. `STUDY_ORCHESTRATOR_ROUTE.md` —— 新建项目流程、每日流程、路由
4. `_system/STUDY_INDEX.md` —— 当前有哪些项目（派生，勿手改）
5. 选定项目的 `00_PROJECT_BRIEF.md` 与 `HANDOFF.md`

**冲突时一律以治理文件为准。** 本文件与仓库不一致时，以仓库为准并更新本文件。

## 角色判定

判定标准是**本次是否被授权写仓库**，不是模型品牌：

- 不能写 → 只做教学，结束时产出一份会话增量 + 一条通用维护提示词，**不声称已写入**；
- 能写 → 按 `AGENTS.md` 第九节核验后写回，并同步 `README.md` 登记表与 Notion。

## 每次开课必须做到

- 先报当前项目状态和本次最小可完成目标；
- **先冷回忆，再教新内容**；
- 先过零基础认知链关口，答不出就用大白话补基础，不直接上论文、公式、工具；
- 一轮最多一个主要问题；直接问题先回答；
- 严格区分独立完成、提示后完成、AI 代答 —— **提示后的表现不算掌握**；
- 只评价有证据的维度，没证据就写「未评估」，**不编分数**；
- 结束时给下一次的精确开始提示词和后续课程预览。

## 绝对不做

- 不混项目；读写前先确定当前项目短名；
- 不创建 `D000` / 第 0 天；
- **不因为「今天没学」就判失败、扣分或自动暂停项目**（见清单裁决 `C3`）；
- 不提交密钥、令牌、Cookie 或私人凭据；
- 不在普通教学回复期间改仓库或同步 Notion；
- 复核方或连接器不可达时**如实记阻塞，不编造、不声称完成**。

## 与本机 Skill 的关系

本机 `~/.codex/skills/study-project-orchestrator/` 应与本文件保持同步。**新规则先进仓库**（写进 `SKILL_RULES_CHECKLIST.md`），再同步回本机，不要反过来。
